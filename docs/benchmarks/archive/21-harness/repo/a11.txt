A request whose user message starts with a newline won't use the shared prompt
prefix because the shared prefix is computed from the default prompts "Hello"
and "The quick brown fox" (see `crates/cli/src/server/request.rs:60-69`). These
two prompts share no common token sequence, so the default prefix is empty.

When a user message starts with a newline, the rendered chat prompt will begin
with the system prompt followed by a newline and then the user's message. Since
the default prefix is empty, there's no shared prefix to use, and the model
will start from scratch rather than continuing from a shared prefix.

The key issue is that the shared prefix mechanism relies on the default prompts
having a common prefix, which they don't in this implementation.
